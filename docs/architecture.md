# PRAYAAN V2 Architecture

## Design principle

PRAYAAN separates **input provenance** from **software execution**. For the SIH demonstration, bus/camera inputs are simulated because an instrumented public fleet is unavailable. The event pipeline, state fusion, geospatial reasoning, prioritisation and visualisation are live software.

## Layers

### 1. Mobile sensing edge

A bus node exposes GPS, heading, speed and four camera channels. In the current demo these are generated by a deterministic simulator. The interface is intentionally compatible with later replacement by real camera inference.

### 2. Evidence event model

An observation contains:

- event and persistent asset identifiers
- event type and subtype
- bus and camera source
- GPS and timestamp
- detector confidence
- evidence provenance

### 3. Cross-bus confidence fusion

Repeated observations of the same persistent city asset increase fused confidence. A single observation remains `UNVERIFIED`; repeated independent observations can promote the issue to `CONFIRMED`.

The current demonstration uses:

`fused_confidence = 1 - (1 - detector_confidence)^observations`

This is a deliberately simple deterministic fusion rule for the V2 foundation. It will later be replaced by spatial clustering + observation independence weighting.

### 4. Urban memory

Persistent assets retain:

- first-seen tick
- number of observations
- number of independent buses
- fused confidence
- persistence duration

This enables future repair verification when later fleet passes stop observing a previously persistent issue.

### 5. Explainable priority

Current V2 priority is:

`100 × (0.45·severity + 0.35·confidence + 0.20·exposure_factor)`

The command center exposes the score components instead of presenting an opaque AI ranking.

### 6. Mobility Intelligence side module

Traffic is intentionally a secondary feature. Fleet-observed corridor speed and congestion are used to demonstrate:

- congestion trend
- route delay estimate
- downstream/spillback risk framing
- same-initial-state what-if comparison

The V2 foundation labels this as a **deterministic what-if model**. SUMO or another microscopic simulator can later become the authoritative engine without changing the UI workflow.

## Demo flow

1. Open City Operations.
2. Watch buses move and paint sensing coverage.
3. Wait for a road/infrastructure event.
4. Open the evidence trace.
5. Observe repeated buses raise fused confidence.
6. Open Urban Memory to show persistence.
7. Open a congested corridor and run the Mobility Digital Twin what-if panel.
8. Explain that simulated fleet input can be replaced by real onboard inference with the rest of the pipeline unchanged.
