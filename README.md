# PRAYAAN V2 — AI-Powered Mobile Urban Intelligence Platform

PRAYAAN V2 is a clean-room rebuild for SIH26124: **AI-Powered Mobile Urban Intelligence Platform Using Public Transport Fleet**.

The core idea is to treat public transport buses as **mobile urban sensing nodes**. In demo mode, a simulated fleet produces GPS, traffic and urban-hazard observations; the software pipeline then performs event processing, confidence scoring, geospatial fusion, prioritisation and city-level visualisation.

## V2 goals

- Judge-facing **urban command centre** rather than a CRUD dashboard.
- Animated city/fleet simulation with explicit **DEMO / simulated input provenance**.
- Evidence-first events: source bus, camera, GPS, timestamp, confidence and reasoning.
- Cross-bus confirmation and spatiotemporal event fusion.
- Urban memory for persistent infrastructure defects.
- Explainable maintenance priority scoring.
- Mobility Intelligence side module for congestion propagation and digital-twin what-if analysis.
- Per-bus **SUMO microscopic traffic twin** with mixed Indian traffic, IDM car-following and LC2013 lane-changing.
- Architecture that can later swap simulated inputs for real bus cameras and edge AI.

## Architecture

```text
Simulated / real bus inputs
        |
        v
Edge event generation
        |
        v
FastAPI urban intelligence backend
        |
        +--> event fusion / confidence
        +--> corridor analytics
        +--> maintenance prioritisation
        +--> mobility intelligence
        +--> SUMO / TraCI micro twins
        |
        v
React + Leaflet + Three.js command centre
```

## Per-bus SUMO Micro Twin

Every simulated fleet bus can be opened as its own microscopic traffic world:

```text
City map
   ↓
Select MTC bus
   ↓
Onboard perception console
   ↓
OPEN MICRO TWIN
   ↓
SUMO generates a deterministic seeded scenario
   ↓
TraCI records vehicle x/y, lane and speed
   ↓
Three.js replays the real SUMO trajectories
```

The scenario contains cars, motorcycles, autos, vans, buses and trucks. A deliberately slower lead vehicle creates car-following and lane-change pressure so the replay demonstrates acceleration, braking, overtaking and local congestion instead of simply moving objects forward.

Available cameras in the micro twin:

- **CHASE** — cinematic third-person view around the PRAYAAN bus.
- **POV** — bus-level forward view.
- **TOP** — network-analysis view.

The UI displays the ego-bus speed, nearby vehicle density, stopped vehicles, vehicle-type mix, simulation seed and physics provenance.

The official `eclipse-sumo` Python wheel is installed through `backend/requirements.txt`; no separate manual SUMO installation is intended for the normal demo workflow.

## Run locally

### Easiest on Windows

Double-click:

```text
run_windows.bat
```

The launcher synchronises backend and frontend dependencies, starts FastAPI on port 8000 and Vite on port 5173, then opens the command centre.

### Manual backend

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### Manual frontend

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`.

Useful checks:

```text
http://localhost:8000/health
http://localhost:8000/api/v2/sumo/status
```

## Demo truthfulness

The V2 demo intentionally distinguishes between:

- **SIMULATED INPUT** — virtual buses/camera observations because we do not own an instrumented public bus fleet.
- **LIVE SOFTWARE** — backend event processing, geospatial logic, fusion, prioritisation, analytics, persistence and UI are executed by the application.
- **LIVE SUMO TRAJECTORIES** — when a bus micro twin is opened, vehicle motion is generated by SUMO and read through TraCI; Three.js only renders those recorded positions.

This distinction is deliberate so the project can be demonstrated honestly while still proving the software architecture.
